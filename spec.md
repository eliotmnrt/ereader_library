# E-Reader Library — Specification

> Status: **v5 — frozen, M1 in progress** · Last updated: 2026-11-12

---

## 0. Vision

A self-hosted personal e-book library. Upload books from a phone or computer, then pull them onto an e-reader (Kobo first, Kindle later) by typing a **short code** shown by the app.

The project has two goals of equal weight:
1. **A tool that is actually used** by me and a few relatives and friends (fewer than 10 users).
2. **A DevOps portfolio project**: the full delivery loop (CI → build → deploy → observability) exists **from the very first commit**, on a "Hello World" app. It is then enriched iteration after iteration.

Constraints:
- **Zero budget**: hosting must be local or on a free tier.
- Low traffic, so the application side is kept as simple as possible. The effort goes into the delivery and operations pipeline.

## 2. Users and roles

- **User**: manages **their own** books only.
- **Admin** (me): everything a user can do, plus creating invitations, listing and deactivating accounts, and viewing storage usage.
- **E-reader**: an **unauthenticated** client. It can only reach the code entry page and the download of the book linked to that code.

Accounts are created **only through an invitation link** generated by the admin.

## 4. "Send to e-reader" flow

### 4.1 Steps

1. On the phone, the user opens a book and taps **"Send to e-reader"**.
2. The app shows a code such as **`KXH-TRP`**, a 15-minute countdown and the short URL to open: `https://<domain>/r`.
3. On the e-reader, the user opens the browser at `/r` and types the code.
4. The page shows the book's title, format and size, with a large **Download** button.
5. The e-reader downloads the file with a proper name and extension.

### 4.2 One site, one special route

There is a **single Next.js app on a single domain**. The `/r/*` route is deliberately minimal:
- server-rendered, **plain HTML with no client-side JavaScript**;
- a classic HTML form (`<form method="POST">`);
- large fonts, maximum contrast, no images, minimal inline CSS;
- no cookies or session required.

The rest of the app (gallery, upload) is meant for phones and computers and can use React and Tailwind normally.

### 4.3 Code rules

- **6 uppercase letters**, with ambiguous characters (I, L, O) excluded. Displayed as `XXX-XXX`, typed without the dash, case-insensitive. Letters only, because e-reader keyboards show letters by default.
- One code maps to **one book**. It is valid for **15 minutes** and can be reused within that window, since downloads on an e-reader can fail.
- A code can be revoked manually. A book has only one active code: generating a new one invalidates the previous one.
- **Brute-force protection**: 10 attempts per minute per IP on `/r`. The code space (23⁶ ≈ 148 M) combined with the short lifetime makes guessing unrealistic.

### 4.4 Target device and format compatibility

**Primary target: Kobo Aura** (2013, old WebKit-based browser). The exact firmware version will be recorded during the M1 test. Kindle support is secondary.

The `/r` page detects the e-reader from its User-Agent. If the format is unsuitable (for example EPUB on a Kindle), the page shows a **warning** but does not block the download.

| E-reader | Readable via the browser | Notes |
|---|---|---|
| Kobo (Aura) | EPUB, PDF, MOBI | Primary target. KEPUB conversion in v2 for better rendering |
| Kindle | MOBI, AZW3, PDF, TXT | The browser refuses EPUB → conversion or Send-to-Kindle in v2 |

### 4.5 Main project risk: the Kobo Aura's browser

Old Kobo browsers are based on an outdated WebKit. Two problems are possible:
- **TLS / certificates**: the device may not support current TLS versions, or may not trust the Let's Encrypt root (ISRG Root X1). In that case it shows a certificate error.
- **Downloads**: the browser may not download files at all, or may not import them into the library.

**Validated in M1** with a dummy `/r` page served over HTTPS. If TLS fails, the fallback options are, in order of preference:
1. Try another certificate chain or authority (for example ZeroSSL, or a different Let's Encrypt chain).
2. Serve **`/r` only over plain HTTP**. This is acceptable because the code is short-lived and a book is not sensitive data. The rest of the app stays HTTPS-only.

If browser downloads do not work, the fallback is an **OPDS feed**, moved up from v2.

**Known limitation to check on the device**: Next.js 16 drops the `Content-Length` header from Route Handler responses and sends downloads with `Transfer-Encoding: chunked`. If the Kobo needs `Content-Length` (for example, the download fails or shows no progress), the fallback is to serve downloads outside Next.js, either through a Traefik buffering middleware or a small dedicated endpoint.

**Test result (2026-11-12, local network, plain HTTP, Kobo Aura)**: everything worked. The page loaded, the form was submitted, EPUB downloaded both as attachment and inline, PDF downloaded, the book appeared in the library and opened. Download progress was shown even without `Content-Length`. Still to test: **HTTPS** (certificate chain on the old firmware). Firmware version not recorded yet.

## 5. Functional requirements

### 5.1 Upload
- Accepted formats: EPUB, PDF, MOBI, AZW3. The format is checked by **file signature (magic bytes)**, not only by extension.
- Maximum size: **200 MB** per file. Quota: **5 GB** per user (configurable).
- Multiple uploads, with one progress bar per file.
- **Duplicate detection** by SHA-256, per user: a duplicate triggers a warning and is not stored.

### 5.2 Processing (asynchronous)
- After upload, the book is created with status `processing`. A worker extracts the metadata, then moves the book to `ready`, or to `failed` with an error message.
- What the worker extracts:
  - **EPUB**: title, author and cover, read from the OPF file;
  - **PDF**: title and author, read from the document metadata;
  - **MOBI / AZW3**: title and author, read from the EXTH header.
- If nothing is found, the file name becomes the title and the author is set to "Unknown".
- The gallery refreshes itself while processing is under way (light polling).

### 5.3 Authentication
- E-mail and password, hashed with **argon2id**. Sessions are stored in the database, with an `httpOnly` / `Secure` / `SameSite=Lax` cookie.
- Every request checks that the resource belongs to the logged-in user.
- Rate limiting on login.

### 5.4 Download
- Every file goes through the app, which **streams** it from Garage (proxy). **Garage is never publicly exposed.**
- With low traffic, the proxy costs almost nothing. It avoids exposing storage and avoids cross-domain redirects, which some e-reader browsers handle poorly.
- `Content-Disposition: attachment; filename="<Author> - <Title>.<ext>"`.

## 6. Non-functional requirements

| Area | Requirement |
|---|---|
| **Load** | Fewer than 10 users, a few concurrent uploads. No horizontal-scaling target, but the app is *stateless*, so several replicas are possible. |
| **Cost** | **€0**: free tiers only (hosting, domain, registry, CI, backups). |
| **Security** | HTTPS everywhere (except the possible `/r` fallback in §4.5); secrets kept out of the repo; Garage and Postgres on a private network; images scanned in CI (Trivy); dependencies watched (Dependabot). |
| **Observability** | Structured JSON logs; `/api/health/live` and `/api/health/ready` (the latter checks Postgres and Garage); Prometheus metrics at `/api/metrics`; Grafana dashboards. |
| **Reliability** | Daily backup: Postgres dump and Garage bucket replication **off the server**. Restore tested at least once. |
| **Quality** | Unit, integration and E2E tests in CI; merging into `main` is blocked when CI is red. |
| **Delivery** | Every merge into `main` is deployed automatically. Rollback by redeploying the previous image tag. |
| **Portability** | Multi-architecture images (**amd64 + arm64**), so the same image runs on a local PC and on an ARM server. |

## 7. Architecture

### 7.1 Overview

```
   Phone / PC               E-reader
        │                       │
        └──────── HTTPS ────────┘
                    │
            ┌───────▼────────┐
            │ Reverse proxy  │  (Traefik: Let's Encrypt TLS)
            └───────┬────────┘
                    │
            ┌───────▼────────┐        ┌──────────────┐
            │  Next.js app   │───────►│    Garage    │ (private)
            │  UI + API + /r │        └──────▲───────┘
            └───────┬────────┘               │
                    │                 ┌──────┴───────┐
            ┌───────▼────────┐        │    Worker    │
            │   PostgreSQL   │◄──────►│ (same image) │
            │  + job queue   │        └──────────────┘
            └────────────────┘
```

### 7.2 Stack

The project is **built brick by brick, by hand, for learning**. Each brick starts with the simplest
tool that works and is upgraded later, as a deliberate step.

| Need | Start with | Upgrade later to |
|---|---|---|
| Runtime | **Node.js 24 LTS**, plain JavaScript | TypeScript |
| Web server | **Express** | — |
| Pages | **Server-rendered HTML with EJS templates** + a classless CSS file (e.g. Pico.css). No React, no build step: ideal for the Kobo | — |
| Database | **SQLite** (one file) | PostgreSQL |
| Book storage | **A folder on disk** (Docker volume) | S3-compatible storage (Garage) |
| Metadata | Extracted **synchronously at upload** | Job queue + worker |
| Auth | Session cookie (`express-session`) + hashed password | Invitations, rate limiting |
| Tests | **`node:test`** (built into Node) + `supertest` | Integration and E2E tests |
| Container | **One Dockerfile** | Docker Compose when Postgres arrives |
| CI | GitHub Actions: lint + tests + image build | Multi-arch images, security scan |
| HTTPS | **Caddy** (automatic HTTPS) | Traefik |
| Deployment | `ssh` + `docker compose up` by hand on Oracle | Automated by CI, then K3s + ArgoCD |
| Monitoring | `/health` endpoint + **Uptime Kuma** | Prometheus + Grafana |

### 7.3 Hosting (€0)

| Target | Role | Details |
|---|---|---|
| **Local** (Docker Desktop / WSL2) | Development, Kobo tests on the home Wi-Fi | `docker compose up`. The Kobo reaches the app through the PC's LAN IP. |
| **Oracle Cloud "Always Free"** | Main production target | Free Ampere ARM instance (up to 4 vCPU / 24 GB RAM, 200 GB disk): enough for K3s, ArgoCD and the Prometheus stack. A bank card is required for identity verification, with no charge. Some regions often lack capacity, and an idle instance can be reclaimed, so it must be monitored. |
| **Fallback if Oracle is unavailable** | Production on a local machine | Exposed through **Cloudflare Tunnel** or **Tailscale Funnel**, both free, with no open ports. |

- **Domain**: a free subdomain from **DuckDNS** (`xxx.duckdns.org`). It supports the Let's Encrypt DNS-01 challenge.
- **Registry**: **GHCR**.
- **CI**: GitHub Actions on a **public repo**, so minutes are unlimited and native arm64 runners are available.
- **Off-server backups**: **Backblaze B2** (10 GB free). It is deliberately with a different provider than Oracle, so losing the Oracle account does not also lose the backups.

## 8. Data model

```
users
  id            uuid PK
  email         text UNIQUE NOT NULL
  display_name  text NOT NULL
  password_hash text NOT NULL
  role          enum('user','admin') DEFAULT 'user'
  is_active     bool DEFAULT true
  created_at    timestamptz

sessions
  id            text PK            -- random token, stored hashed
  user_id       uuid FK → users
  expires_at    timestamptz
  created_at    timestamptz

invitations
  id            uuid PK
  token_hash    text UNIQUE
  created_by    uuid FK → users
  expires_at    timestamptz
  used_by       uuid FK → users NULL
  used_at       timestamptz NULL

books
  id                uuid PK
  owner_id          uuid FK → users
  title             text NOT NULL
  author            text NULL
  format            enum('epub','pdf','mobi','azw3')
  original_filename text
  storage_key       text           -- e.g. books/<owner_id>/<book_id>
  cover_key         text NULL
  size_bytes        bigint
  sha256            char(64)
  status            enum('processing','ready','failed')
  error             text NULL
  created_at        timestamptz
  updated_at        timestamptz
  UNIQUE (owner_id, sha256)

transfer_codes
  code           char(6) PK      -- only one active code at a given time
  book_id        uuid FK → books ON DELETE CASCADE
  created_by     uuid FK → users
  expires_at     timestamptz
  revoked_at     timestamptz NULL
  download_count int DEFAULT 0
  created_at     timestamptz
```

The job tables are managed by pg-boss in a dedicated schema.

## 10. DevOps

### 10.1 Monorepo layout

```
ereader_library/
├── apps/
│   └── web/                 # Next.js app; the worker is a second entrypoint (src/worker.ts)
├── infra/
│   ├── compose/             # docker-compose for local dev + stage A
│   ├── garage/              # Garage config + idempotent init script
│   ├── scripts/             # deploy, smoke test, secret generation
│   ├── k8s/
│   │   ├── base/            # Kustomize base (app, worker, postgres, garage)
│   │   └── overlays/        # staging / prod
│   └── argocd/              # ArgoCD Applications (stage C)
├── .github/workflows/       # CI/CD
├── docs/                    # spec, runbooks
└── README.md
```

- Package manager: **pnpm** (workspaces).
- At stage C, CI writes the new image tag into `infra/k8s/overlays/*`. To avoid that commit re-triggering CI, the pipeline uses `paths` filters and `[skip ci]`. An alternative is ArgoCD Image Updater.

### 10.2 Environments
- **local**: `pnpm stack:up` starts the app, Postgres and Garage (and the worker from M3).
- **prod**: the Oracle free instance (or the local fallback). A **staging** namespace is added from stage B on, on the same machine.

### 10.3 CI/CD pipeline (GitHub Actions)

```
PR   : lint → typecheck → unit tests → integration tests (Testcontainers) → multi-arch build → Trivy scan
main : (same) → push image to GHCR (tag = commit SHA) → migrations → deploy → smoke test /api/health/ready
```

### 10.4 Infrastructure stages

| Stage | Deployment | Observability |
|---|---|---|
| **A — day one** | Docker Compose on the server, deployed by GitHub Actions over SSH; Traefik + Let's Encrypt (DuckDNS) | Health checks, JSON logs (`docker logs`) |
| **B** | **K3s** on the server; Kustomize manifests; `staging` / `prod` namespaces | Prometheus + Grafana; Loki for logs |
| **C** | **GitOps with ArgoCD**: CI bumps the image tag in `infra/`, ArgoCD syncs | Alerting (Alertmanager), SLO dashboards |
| **D** (optional) | Infrastructure as Code for the Oracle instance (OpenTofu); secrets with SOPS or Sealed Secrets | |

## 11. Roadmap

Principle: **small bricks, each one understood and working before the next**.
The DevOps loop arrives early (bricks 3 to 5) and grows afterwards.

1. **Hello Express**: an Express app running locally, with a `/health` route.
2. **`/r` on the Kobo**: plain-HTML code form + demo book download, tested on the Kobo Aura over the home Wi-Fi.
3. **Docker**: the app runs in a container.
4. **GitHub + CI**: repo, lint and tests on every push.
5. **First deployment**: by hand on Oracle with Caddy, then the Kobo test over **HTTPS**.
6. **Library**: upload to a folder, SQLite, metadata extraction, gallery.
7. **Auth**: login, sessions, invitations.
8. **Real transfer codes**: the app becomes usable day to day.
9. **DevOps bricks, one at a time**: automated deployment, Postgres, S3 storage, backups, monitoring, K3s, ArgoCD.
10. **Next**: v2 features (KEPUB conversion, OPDS, Send-to-Kindle…).

## 12. Decisions

| # | Decision | Rejected alternative |
|---|---|---|
| D1 | Express + EJS server-rendered pages, in JavaScript | Next.js: too much magic to learn the fundamentals; React is not needed (and not wanted on the Kobo) |
| D2 | Start simple (SQLite, local folder, synchronous processing) and upgrade brick by brick | Target architecture from day one |
| D3 | Upload and download go through the app (proxy); Garage stays private | Direct signed URLs: Garage exposed, risky redirects on e-readers |
| D4 | 6-letter code valid for 15 minutes, tied to one book | Long signed link, impossible to type on an e-reader |
| D5 | One app, with a JavaScript-free `/r` route | Two separate sites |
| D6 | Invite-only accounts | Public sign-up |
| D7 | Progressive infrastructure: Compose → K3s → ArgoCD | Kubernetes and GitOps from day one, which would delay the first production release |
| D8 | €0 hosting: Oracle Always Free (ARM), with a local fallback | Paid VPS |
| D9 | Multi-arch images (amd64 + arm64) | Single-architecture image |
| D10 | Monorepo (app + infra) | Separate infra repo |
| D11 | Primary target: Kobo Aura | Kindle first |
| D12 | Documentation in English | French |
| D13 | Public GitHub repo `ereader_library` | Private repo (limited CI minutes, no free arm64 runners) |
| D14 | Backups on Backblaze B2 | Oracle Object Storage (same provider as production) |
| D15 | Garage for object storage | MinIO: the community edition no longer ships Docker images (checked 2026-11-12) |
| D16 | Built by hand, brick by brick (Claude guides and reviews, does not write the code) | Generated walking skeleton (tried on 2026-11-12, then deleted) |
